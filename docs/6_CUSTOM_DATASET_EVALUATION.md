# 6. Custom Dataset Evaluation

How SENTRIX is measured against the team's own labelled footage, and what the
shipped v3 models score on it. Every number below is generated by
`python tools/custom_eval_table.py` from reports committed under
[`training/runs/custom_eval/`](../training/runs/custom_eval/).

---

## 6.1 The dataset

765 hand-reviewed frames from 10 source videos, five single-label classes.

| idx | class | train | val | test | total |
|---|---|---|---|---|---|
| 0 | normal | 373 | 23 | 67 | 463 |
| 1 | fire | 11 | 6 | 0 | 17 |
| 2 | weapon | 144 | 55 | 26 | 225 |
| 3 | assault | 43 | 0 | 0 | 43 |
| 4 | robbery | 17 | 0 | 0 | 17 |

* **Splits are by source video** — train: `vid02 vid03 vid05 vid06 vid07 wa01 wa03`;
  val: `gun vid04`; test: `wa02`. No video contributes to two splits.
* **Two locations only**: a bedroom (`vid*`, `gun`; handguns and aerosol flame
  jets) and a corridor filmed by CCTV (`wa*`; a long stick, an assault, a
  bicycle theft).
* **Coverage gaps**: val has no assault or robbery; test has no fire, assault or
  robbery. Robbery is a single event in a single training video, so its recall
  cannot be measured on this dataset at all.

The images (80 MB) stay outside the repository. Their ground truth is vendored
in [`training/datasets/sentrix_custom/`](../training/datasets/sentrix_custom/)
(`labels.csv`, `frames.csv`, `segments.csv`, …) together with `videos.csv`,
which maps each video id to its source file. Point the tools at the data with
`SENTRIX_CUSTOM_DATASET` and `SENTRIX_CUSTOM_VIDEOS` (see `.env.example`).

## 6.2 Two measurements, one code path

Both go through the product pipeline (`Pipeline._observe` / `Pipeline.process`
and `TCIEngine`), never a parallel evaluation path.

| | Per-image | Video replay (end to end) |
|---|---|---|
| Command | `python tools/eval_custom_frames.py` | `python tools/replay_custom_videos.py` |
| Input | the 765 labelled images | the 10 source videos |
| How | each image is a static clip: two observations one violence hop apart, all temporal state reset per image | native-rate decode, `process()` at the 6 Hz inference rate with true timestamps: windows, EMA, hysteresis and incident typing all live |
| Ground truth | the image label | reviewed label timeline (below) |
| Prediction | TCI incident type → dataset class | same |

**Prediction mapping.** The TCI engine's incident type is the system's verdict:
`fire`, `weapon`, `assault` and `robbery` map to themselves. `intrusion` (an
unrecognised person) maps to `normal`, because nobody in this footage is
enrolled, so it would fire on every person and says nothing about threats.

**Harness isolation** (`sentrix/evaluation/harness.py`):

* every side effect is disabled — no evidence, snapshots, SMS, calls, siren or
  database rows. `.env` in a developer checkout carries live Twilio credentials;
* identity is neutral — everyone is an unrecognised, non-degraded person. The
  dataset has no authorisation labels, and a match against whoever happens to be
  enrolled on the machine would floor the TCI and hide the signal being measured;
* no microphone — live room audio is uncorrelated with a replayed clip.

**Replay ground truth** (`sentrix.evaluation.custom_dataset.Timeline`) is built
from every sampled frame in `frames.csv` (3–8 fps). Kept frames carry their
reviewed label. A dropped near-duplicate inherits its kept twin's label if the
twin is within 1 s; otherwise it keeps its own segment label if that segment was
confident (≥ 0.7), otherwise it is unscored. The one-second limit matters:
pHash barely registers a flame jet, so a "duplicate" 5 s away can differ in
exactly the object that decides the label. A replay tick is scored against the
nearest sample within 0.25 s.

**Metrics** (`sentrix/evaluation/metrics.py`):

* *Macro-F1* averages only the classes present in the ground truth of that split
  (the test split has two), so a perfect model scores 1.0, not 0.4. Predicting an
  absent class still costs recall of the true class.
* *Threat recall / FPR*: normal vs any threat. A weapon called "assault" is a
  detected threat of the wrong type.
* *Episodes*: a contiguous ground-truth threat run is detected if the matching
  class is predicted between its start and 1 s after its end.
* *False alarms*: maximal runs of threat predictions on ground-truth-normal ticks
  lying more than 1 s from any threat episode, per minute of normal footage.

## 6.3 Baseline: the shipped v3 models (`sentrix/baseline-v3`)

Models: `yolov8n.pt` (person), `weapon_detector_real_v3.pt`,
`fire_smoke_detector_real_v3.pt`, `violence_classifier_real_v3.pt`, 5-feature
XGBoost fusion. None of them saw this data, so every split — train included — is
out of sample for the baseline.

### Per-image evaluation

| Run | Split | n | Accuracy | Macro-F1 | Threat recall | Threat FPR | Weapon F1 | Fire F1 | Assault F1 |
|---|---|---|---|---|---|---|---|---|---|
| baseline | train | 588 | 0.566 | 0.280 | 0.688 | 0.308 | 0.429 | 0.000 | 0.230 |
| baseline | val | 84 | 0.417 | 0.281 | 0.197 | 0.000 | 0.358 | 0.000 | - |
| baseline | test | 93 | 0.043 | 0.114 | 1.000 | 1.000 | 0.229 | - | - |

### Video replay (end to end)

| Run | Videos | Ticks | Accuracy | Macro-F1 | Threat recall | Threat FPR | Episodes detected | False alarms / normal min |
|---|---|---|---|---|---|---|---|---|
| baseline | all | 1759 | 0.459 | 0.221 | 0.673 | 0.471 | 14/18 | 13.96 |
| baseline | val | 153 | 0.516 | 0.318 | 0.151 | 0.000 | 1/2 | 0.00 |
| baseline | test | 250 | 0.052 | 0.157 | 1.000 | 0.976 | 3/3 | 20.39 |
| baseline | train | 1356 | 0.528 | 0.248 | 0.755 | 0.398 | 10/13 | 13.34 |

Pipeline latency during replay: mean 96.8 ms, p95 185.9 ms per tick (CPU).

### What goes wrong, per model

Raw scores on all 765 images (`AUROC` of the class vs `normal`):

| Model | Signal | AUROC | At the production threshold |
|---|---|---|---|
| `weapon_detector_real_v3` | max weapon confidence | 0.54 | fires on 29 % of weapon frames **and 8 % of normal frames** (≥ 0.55) |
| `fire_smoke_detector_real_v3` | max fire/smoke confidence | 0.43 | detects **none** of the 17 aerosol flame jets (≥ 0.50) |
| `violence_classifier_real_v3` | P(fight) | 0.70 (assault) | scores ≈ 0.82 on **every** frame of the test corridor, normal ones included |

* **The corridor looks like a fight to the RWF-2000 model.** The violence
  classifier labels the whole of `wa02` as assault, empty corridor included —
  most likely because grey top-down CCTV is what RWF-2000's fight clips look
  like. That single failure produces the 0.043 test accuracy and 20 false
  alarms per minute.
* **Weapon detection is close to chance on handguns held at close range**, and
  the three-class head (knife, long_gun, pistol) has no class for the stick used
  in the corridor.
* **Fire is never detected.** None of the 17 hand-held aerosol flame jets
  produces a fire or smoke box at the 0.50 gate; the v3 detector does not
  transfer to this kind of flame.
* **Robbery has no signal at all** — no model produces it.

These are not threshold problems: at AUROC 0.54 there is no weapon threshold
that separates the classes. The models need to see this domain, which is what
the `sentrix/finetuned-v3` and `sentrix/custom-v4` branches do.

## 6.4 Reproducing

```bash
python tools/eval_custom_frames.py --splits train,val,test --tag baseline
python tools/replay_custom_videos.py --videos all --tag baseline
python tools/custom_eval_table.py baseline
```

`--rescore` on the replay tool recomputes metrics from the saved per-tick CSV
without replaying.
